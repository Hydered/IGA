# IGA — управление согласованием ИТ-доступов

Веб-приложение для подачи заявок на доступ к ИТ-ресурсам, согласования по маршруту и фиксации выдачи доступа. Интерфейс и API на русском языке.

## Возможности

- создание заявки с указанием ресурса, типа доступа, срока действия, основания и обоснования;
- настраиваемый маршрут согласования (несколько согласующих по порядку);
- статусы: новая, на согласовании, требуется уточнение, согласована, отклонена, выполнена, закрыта;
- комментарии и вложения к заявке;
- журнал изменений по заявке;
- отчёт по заявкам (для ролей с правом просмотра);
- разграничение доступа по ролям и проверка прав на уровне API.

## Стек

- Node.js, Express
- SQLite
- JWT, bcrypt
- статический фронтенд (`public/`)

## Требования

- Node.js 18 или новее
- npm

На Windows для сборки `better-sqlite3` может понадобиться [инструменты сборки Visual Studio](https://visualstudio.microsoft.com/visual-cpp-build-tools/). После смены версии Node выполните `npm rebuild` в каталоге проекта.

## Установка и запуск

```bash
npm install
npm run init-db   # первичное создание БД (если файла data/iga.db ещё нет)
npm start
```

Приложение откроется по адресу http://localhost:3000 (порт задаётся переменной `PORT`).

Режим с автоперезагрузкой при изменении кода:

```bash
npm run dev
```

## Учётные записи по умолчанию

После инициализации БД доступны тестовые пользователи. Пароль у всех: `password123`.

| Логин        | Роль                    |
|--------------|-------------------------|
| applicant    | Заявитель               |
| approver     | Согласующий             |
| route_admin  | Администратор маршрутов |
| executor     | Исполнитель             |
| admin        | Администратор           |

Использовать эти учётки в production не следует.

## Роли

| Код в системе | Назначение |
|---------------|------------|
| `applicant`   | Создаёт заявки, редактирует свои заявки до согласования, отправляет на согласование |
| `approver`    | Принимает решение по заявкам, где указан в маршруте |
| `route_admin` | Просматривает заявки, редактирует маршрут согласования |
| `executor`    | Отмечает выдачу доступа и закрывает заявку |
| `admin`       | Полный доступ к операциям в рамках бизнес-правил |

Пользователь видит только те заявки, к которым у него есть право (свои, из маршрута согласования или по роли с общим доступом).

## Типы доступа

Справочник при инициализации БД:

- чтение
- запись
- полный доступ
- администрирование

## Поле «Основание»

Обязательная ссылка на внутренний нормативный документ или заявку HR (например, `HR-2024-001` или URL). Максимальная длина — 500 символов.

## Жизненный цикл заявки

```
новая → на согласовании → согласована → выполнена → закрыта
              ↓
      требуется уточнение → (повторно) на согласовании
              ↓
           отклонена
```

## Переменные окружения

| Переменная | Описание | По умолчанию |
|------------|----------|--------------|
| `PORT` | Порт HTTP-сервера | `3000` |
| `NODE_ENV` | Режим (`production` включает проверку секрета JWT) | — |
| `JWT_SECRET` | Секрет подписи токенов; обязателен в production | dev-значение (только для разработки) |
| `JWT_EXPIRES_IN` | Срок жизни токена | `8h` |
| `IGA_DB_PATH` | Путь к файлу SQLite | `data/iga.db` |
| `CORS_ORIGIN` | Разрешённые origins через запятую | localhost на текущем порту |
| `LOGIN_RATE_LIMIT_MAX` | Лимит попыток входа за окно | `20` |
| `IGA_RESET_DB` | При `true` пересоздаёт БД при старте (не в production) | — |

Пример для production (PowerShell):

```powershell
$env:NODE_ENV = "production"
$env:JWT_SECRET = "<случайная строка не короче 32 символов>"
$env:CORS_ORIGIN = "https://iga.example.local"
npm start
```

## База данных

- Схема: `src/db/schema.sql`
- Инициализация: `npm run init-db` или автоматически при первом запуске, если БД пуста
- При повторном запуске существующие данные сохраняются; полный сброс в dev: `IGA_RESET_DB=true npm run init-db`
- При обновлении схемы выполняется лёгкая миграция (например, добавление колонки `basis`)

Каталоги данных: `data/`, вложения: `uploads/`, логи: `logs/`.

## API

Префикс: `/api`. Авторизация: заголовок `Authorization: Bearer <token>` (кроме `POST /api/auth/login`).

| Метод | Путь | Назначение |
|-------|------|------------|
| POST | `/auth/login` | Вход |
| GET | `/auth/me` | Текущий пользователь |
| GET/POST | `/requests` | Список / создание заявок |
| GET/PUT | `/requests/:id` | Просмотр / изменение |
| PUT | `/requests/:id/approvers` | Маршрут согласования |
| POST | `/requests/:id/submit` | Отправка на согласование |
| POST | `/requests/:id/approve` | Решение согласующего |
| POST | `/requests/:id/complete` | Выполнение |
| POST | `/requests/:id/close` | Закрытие |
| POST | `/files/:requestId` | Загрузка вложения |
| GET | `/files/:id/download` | Скачивание вложения |
| GET | `/catalog/*` | Справочники |
| GET | `/reports` | Отчёт |

Проверка состояния: `GET /api/health`.

## Структура проекта

```
src/
  index.js              # точка входа, middleware
  config/               # конфигурация
  constants/            # статусы, роли, лимиты полей
  db/                   # схема, инициализация
  middleware/           # JWT, обработка ошибок
  routes/               # HTTP-маршруты
  services/             # бизнес-логика
  repositories/         # доступ к БД
  utils/                # валидация, ответы HTTP
public/                 # HTML, CSS, JS
tests/
data/
uploads/
logs/
```

## Безопасность

- пароли хранятся в виде bcrypt-хеша;
- доступ к заявкам и файлам проверяется на сервере;
- ограничение частоты запросов на вход;
- заголовки Helmet, ограничение CORS и размера JSON-тела;
- в production требуется собственный `JWT_SECRET`.
